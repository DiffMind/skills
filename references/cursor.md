# Cursor 原生 MCP

按 [connection.md](connection.md) 的固定分流，当前客户端使用原生 OAuth，不使用配对码；实际能力只影响自动执行或人工步骤，不更换认证方式。不得复制其他客户端凭据。

只在当前智能体为 Cursor 时读取。先遵守 SKILL.md 的固定连接目标、连接确认和付费确认；不安装或调用 Codex。当前对话刚刚安装或重新安装本 Skill 包时，不得复用已有登录，必须重新授权；完成前不检索。

## 配置与授权

1. 先检查 Cursor 已加载的原生工具及对应 MCP URL。没有新安装或重新安装，且地址正确、这次授权已完成时可以继续。刚安装或重新安装后要重新授权，不能因为旧工具还在就直接检索。未连接时使用 Cursor 实际提供的 MCP 管理能力；没有自动管理能力时，引导用户在 Customize／MCP 中添加远程服务器。
2. 有权编辑配置时，保留用户现有 JSON 和其他服务器，仅合并以下条目。项目范围使用 `.cursor/mcp.json`，全局使用 `~/.cursor/mcp.json`；用户已指定范围则沿用，不同时写两处。无范围偏好且项目不明确时先用设置入口，避免猜测目录。

```json
{
  "mcpServers": {
    "diffmind-open": {
      "url": "https://mcp.diffmind.ai/mcp/open"
    }
  }
}
```

3. 同名且 URL 不同或已有手动凭据时保留原配置并使用未占用名称；不把认证头、密钥或其他连接的 Token 填入。使用 Cursor 自带的连接／登录操作，由 Cursor 完成 OAuth PKCE、DCR、回调及凭据刷新，用户本人确认授权。
4. 如果当前版本提供 scope 选择，首次连接同时选择 `web:search` 与 `model:chat`，并告知用户分别对应检索和模型聊天；用户明确要求限制为单项时遵从用户。不为设置 scopes 凭空创建 client_id 或 client_secret。若当前 DCR 流程只能默认申请权限，先如实展示实际授权范围让用户决定，不假称已获得两项权限。
5. 授权后在 Cursor 内刷新并核对工具和目标 URL，继续用户原任务；需要本次付费确认。工具未出现时检查是否启用及工作区／团队策略，不以 Codex 中的工具列表作为证据。

## 回调兼容限制

桌面客户端和云端 Agent 使用的回调地址不同，动态登记可能同时带上两者。若授权被拒绝，说明服务还没有接受该回调，桌面版也可能遇到。

出现该错误时说明管理员需确认并适配 Cursor 的可信 HTTPS 回调，保持用户请求待办；不自动改服务器、不反复登录、不创建未登记静态客户端，也不借助 Codex 绕行。官方支持静态客户端不代表当前 DiffMind 已有可用的预注册应用。

本地 MCP URL 只有客户端能实际访问该机器才可用，Cursor 云端 Agent 不能访问用户电脑的 localhost。超时或结果未知时不重新发起付费请求。

依据：[Cursor MCP 官方文档](https://prod.cursor.com/docs/mcp)。界面名以当前客户端为准；本说明不是已完成端到端验收的声明。
