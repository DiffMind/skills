# 配对码连接

本方式固定用于 WorkBuddy、豆包；Codex、Cursor、Claude 使用原生 OAuth，不在本说明中通过配对兜底。先收齐邮箱与配对码，随后确认安全输入、凭据保护和调用通路可完成；不能绕过账号、权限或替换授权校验。

## 用户引导

“DiffMind AI 已安装。当前使用配对码连接：请打开 [DiffMind 网站](https://www.diffmind.ai)，进入「个人资料 → 凭证」，生成配对码后继续完成配对。请勿发送密码或长期访问令牌。”

**先收齐邮箱和配对码，再检查和连接。** 每次收到配对相关回复，先只核对当前对话是否已有这两项；缺少信息时立即索取缺项并等待，不先读取配置、检查 Python／网络／存储、发现工具、编写脚本或请求兑换接口，不重复索取已提供的信息。仅收到配对码时回复：“配对码已收到，请再提供你的 DiffMind 登录邮箱，用于核对配对账号。”仅收到邮箱时回复：“邮箱已收到，请再提供你在 [DiffMind 网站](https://www.diffmind.ai)「个人资料 → 凭证」生成的配对码。”两项都没有时一次索取：“请提供你的 DiffMind 登录邮箱和刚生成的配对码，用于完成账号配对。”不要复述用户提供的配对码。两项收齐且用户要求继续配对后，再检查安全输入、凭据保护和连接通路，沿用已有检查结果；能力不足时说明实际限制，不兑换、不持久保存敏感输入。 不要让用户发送 Cookie、密码或现有访问令牌。

## 有效 Token 与工具调用

**配对码兑换成功返回的 `data.accessToken` 就是有效的 MCP 访问 Token，账号授权至此完成。使用 `Authorization: Bearer <token>` 请求固定 MCP 地址即可在其权限范围内调用工具，无需再次 OAuth、网页授权或重新生成配对码。** Token 有效不等于智能体已加载原生工具；原生目录没有 DiffMind 工具时，先使用本次 Token 建立可用调用通路，不能直接判定未授权或只能让用户点 Trust。

## 配对成功后的连接更新顺序（必须执行）

1. **取得新 Token。** 使用兑换返回的 `data.accessToken`，不是一次性配对码；兑换成功即账号授权成功，无需再走 OAuth。
2. **替换当前 DiffMind 连接的旧凭据。** 核对当前智能体实际使用的配置位置、服务器名称和固定 URL，只更新对应连接的认证字段或凭据存储，保留其他连接与无关配置。WorkBuddy 使用 `mcp.json` 时，必须先核实其实际支持的认证格式，再按该格式保存新 Token；不能猜测 `auth` 字段结构、重复新增同目标连接或只更新临时脚本。凭据不得出现在代码仓库、Skill、命令参数、普通日志或对话输出中；支持凭据引用时优先引用受保护存储。
3. **让运行中的连接采用新凭据。** 执行当前智能体真实提供的重连、配置重载或连接刷新操作。文件已更新不代表运行中的连接已更新；另起临时进程也不代表原生连接已刷新。不虚构操作能力、不跳过智能体要求的审批。
4. **验证原生连接。** 使用当前智能体的只读工具发现或 `tools/list`，核实连接已就绪。仅有缓存工具名不等于验证新凭据成功；可通过该连接的只读调用验证认证，不用付费搜索或模型生成探活。失败先区分旧凭据缓存、配置未生效、权限和网络问题，不立即重配或改走 HTTP。配置或保存失败时先处理该错误，不能用 HTTP 掩盖未完成的持久连接更新。
5. **仅在确认当前会话无法重载时临时使用 HTTP。** 完成凭据配置更新，并核实当前智能体没有可用重载能力或实际重载明确失败后，才允许以同一新 Token 建立直接 MCP HTTP 调用通路。只有该限制实际阻断当前任务时才说明必要下一步；HTTP 已完成调用时只交付任务结果，不附原生连接未加载或 Trust 提示。原生工具目录为空本身不是启用后备通路的充分依据。后续原生连接恢复后优先使用原生工具，不把临时脚本作为每次调用的固定方式。智能体要求用户操作时给出真实步骤，不绕过审批。

### 已验证通路的复用

遵守 SKILL.md 的“只读查询与已验证连接复用”：同一目标与凭据版本下，已确认无法重载且 HTTP 通路已验证时，直接复用实际配置引用和工具 schema 执行后续只读请求。不反复搜索原生工具、确认是否需要付费、读取同一凭据文件或为相同流程重写脚本。新的 HTTP 传输确需初始化时仍按协议初始化；服务端要求新会话、schema 改变或认证错误时只恢复相应部分。不能复用已失效的会话或旧 Token。

### 复用包内只读客户端

满足第 5 步且原生连接不可用时，模型列表和只读发现统一使用 [../scripts/pairing_readonly.mjs](../scripts/pairing_readonly.mjs)，不再现场编写、删除、重新编写等价脚本。脚本使用 Node.js 18+ 标准库，不安装依赖；Node 可用性只核实一次，不因缺少运行时扩展为全盘搜索或自动安装。

```sh
node <本Skill目录>/scripts/pairing_readonly.mjs --config <已确认的mcp.json路径> --server <已确认的连接名> --models
```

`--models` 只调用 `diffmind_models_list`；`--check` 只做协议初始化和工具发现，返回工具名称与完整 inputSchema。二者每次只选一个。查询模型时直接用 `--models`，不要先重复运行 `--check`。复用已确认的配置路径，脚本每次只读取一次该连接的 `headers.Authorization`，不接受命令行 Token、不兑换配对码、不修改配置、不发起搜索或生成。其他凭据管理方式不兼容时报告具体限制，不复制凭据来适配脚本。

脚本在单次调用内完成必要握手、会话头和实际 schema 校验、JSON/SSE 解析及结果输出，失败只返回诊断码。它是短期 HTTP 客户端，每次启动可能需要新的协议握手；不要把这一必要动作扩大为重新检查授权、环境或原生连接。输出完整结果，可能包含 `content[].text` 或 `structuredContent`，据真实结果展示模型列表；不将脚本的原始 JSON、内部计费枚举或连接方式说明作为面向用户的默认回答。不得因没有预先打印 schema 就另写脚本补查，客户端会在调用前校验。

### 临时 HTTP 调用要求

满足上方第 5 步且有安全携带凭据的 HTTP 执行能力时，完成 `initialize` 和 `notifications/initialized`，通过只读 `tools/list` 获取实际 schema，再按原任务用 `tools/call` 调用同一 MCP 地址。按服务端响应维护协议版本和会话头；不是直接请求工具名对应的 REST 路径。复用已确认的配置与凭据引用，不为每次调用重新搜索凭据文件、重复兑换或要求用户再次提供配对码。凭据仅保留在受保护存储或受控进程内，不打印认证头或原始兑换响应。真实付费调用仍需按 SKILL.md 确认。

仅在智能体实际要求 Trust／启用／审批时提示对应操作，不作为兑换后的固定步骤；缺少安全存储、调用能力或操作被拒绝时，如实报告具体阻塞。

## 兑换与凭据处理

1. 邮箱与配对码均已收齐、用户选择继续配对且能力检查通过后，仅 POST `https://mcp.diffmind.ai/mcp/code/token`，使用 `Content-Type: application/json`，请求体为 `{"pairingCode":"用户提供的码","email":"用户提供的邮箱"}`。不把码、邮箱、响应 Token 写入命令参数、临时项目文件、持久日志或面向用户的工具输出；无法抑制敏感响应展示时停止并说明限制。
2. 返回 `existing_grant` 时，不反复请求。告知“继续配对会使已有授权失效，是否继续？”，取得明确同意后，用同一码和邮箱增加 `"replaceExisting":true` 再提交。拒绝就停止，不擅自撤销或换码。
3. 成功从 `data.accessToken` 读取凭据，只通过当前智能体支持的受保护存储／凭据配置方式保存和使用，不跨客户端复制，不写入 Skill、代码仓库或普通 JSON 明文日志。不修改其他连接，不将 OpenAI 专用 extensions 原样写入不同智能体的 MCP 配置。
4. 兑换成功即如实确认“DiffMind AI 账号配对授权成功”，并按 SKILL.md 完整展示用途和示例；连接或工具尚未就绪不省略介绍，另简短说明实际状态和下一步。仅在保存、连接和当前工具验证都成功后才说“DiffMind AI 已连接”。如智能体要求 Trust、启用、连接或用户审批，给出真实步骤并等待，不跳过、代签或伪造。必要时可解释凭据用途及存储方式，但不展示凭据值。
5. 失败时区分码失效、账号不匹配、网络或存储错误。简短说明真实原因及下一步；仅当码确实失效时请用户重新生成，不一概要求重配。更新或刷新按当前智能体实际支持的方式和服务端返回处理，不自行设计未实现的刷新机制。

配对完成只解决身份连接；每次新的付费搜索或模型批次仍需独立费用确认。原任务存在时继续处理，不擅自探活扣点。

安装后先输出配对引导和必要下一步，不展开安装报告，不要求用户先回复“继续配对”；缺少邮箱或配对码时先立即索取缺项，收齐后再检查能力。不要将内部核验过程逐条复述给用户。

授权成功介绍统一引用 SKILL.md 的 AUTH_SUCCESS_COPY_START 至 AUTH_SUCCESS_COPY_END 固定文案，逐字输出其中正文且不输出标记；不得改写、删减或替换示例。客户端差异仅影响授权步骤和必要的真实状态补充，不改变介绍文案。
