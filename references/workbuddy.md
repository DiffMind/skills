# WorkBuddy：固定使用配对码

本 Skill 在 WorkBuddy 中固定走配对码。安装后直接发出以下引导，不先问是否打开 OAuth，不把“能打开浏览器”“有登录按钮”或“服务端支持 OAuth”当作已完成原生接入的证据。这是当前 Skill 的接入策略，不是对 WorkBuddy 产品整体能力的判断。

> DiffMind AI 已安装。请打开 [DiffMind 网站](https://app.diffmind.ai)，进入「个人资料 → 凭证」，生成配对码后继续完成配对。请勿发送密码或长期访问令牌。

## 安装与配对

1. 安装文件后立即输出上述引导，不只报告安装路径、文件校验和下一轮可用。用户明确只安装、不连接时停止。
2. 按 [pairing.md](pairing.md) 先收齐 DiffMind 登录邮箱与配对码。缺少任一项时立即只索取缺项，不先检查环境、配置、网络或工具，不重复索取已提供的信息。两项齐全后再检查安全输入、凭据保护和连接使用能力；能力不足时说明实际限制，不自行转去浏览器 OAuth。
3. 两项输入齐全、用户选择配对且能力检查通过后，按 pairing.md 的固定端点兑换，返回 existing_grant 时确认替换影响，不擅自撤销已有授权。
4. 兑换成功即取得有效访问 Token，账号授权已经完成，按 pairing.md 使用 `Authorization: Bearer <token>` 调用 MCP 工具，无需再次 OAuth。必须按 pairing.md 的五步顺序执行：更新当前 DiffMind 连接的旧 Token，保留其他连接，重连／重载后验证原生工具。不能仅更新文件就认为运行中的连接已刷新；只有确认当前会话无法重载时才临时使用安全的 MCP HTTP 通路，不能因工具目录为空就直接回退。URL 为 `https://mcp.diffmind.ai/mcp/open`，认证使用本次兑换的凭据；不能只写 URL 再期待自动走 OAuth。不得复制 packaging 下 Codex 专用的 OAuth 配置或借用 Codex CLI。凭据不写入代码仓库、Skill、命令参数或对话输出。
5. 仅在智能体实际要求 Trust、启用、连接或审批时引导用户操作，不将其作为配对后的固定下一步；不能在未核实连接与凭据配置时反复要求用户点 Trust。允许智能体要求的必要审批，不跳过、代签或伪造。保留其他连接；已有同目标的未完成 OAuth 连接时不反复点授权，不自动删除或清空凭据，先说明后续将改为配对；实际变更按用户授权范围和智能体管理能力执行。
6. 分别记录“配对凭据已取得”“连接已配置”“当前工具已就绪”。只有当前智能体能实际发现目标工具才报告已连接；凭据已取得但工具未加载时说明加载问题，不错误提示用户网页授权失败，不让用户重复生成配对码。

本 Skill 不提供 WorkBuddy OAuth 分支。配对通路不可用时说明限制及下一步，不因浏览器可以打开而切换方式。此规则不代表 WorkBuddy 产品整体不支持 OAuth，也不绕过服务端账号与权限校验。付费调用仍须另行确认。

回复遵守 SKILL.md 的两阶段规则：安装后只给对应授权引导与必要下一步；本次首次授权成功后完整展示用途和示例，不只报告连接状态。工具未热加载时单独说明真实限制，不据此跳过介绍；用户明确不需要介绍时遵从用户。

授权成功介绍统一引用 SKILL.md 的 AUTH_SUCCESS_COPY_START 至 AUTH_SUCCESS_COPY_END 固定文案，逐字输出其中正文且不输出标记；不得改写、删减或替换示例。客户端差异仅影响授权步骤和必要的真实状态补充，不改变介绍文案。

只读模型列表查询直接调用 `diffmind_models_list`，不先查批次或请求扣点确认。连接已检查且状态未变化时，按 SKILL.md 的“只读查询与已验证连接复用”执行，不重复探测、重写脚本或再次要求 Trust。

已满足 HTTP 后备条件的只读模型查询，直接复用 pairing.md 的包内 `pairing_readonly.mjs --models`，不先再检查一轮或重新编写等价脚本。查询成功只交付模型列表，不追加原生未加载、Trust 或连接说明；仅当真实错误阻断本次任务时说明必要下一步。
