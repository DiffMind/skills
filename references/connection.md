安装、导入、更新或重装后，先识别当前客户端，在同一次安装回复中输出 SKILL.md 对应引导。不再探测 OAuth 能力决定认证方式；能力检查只用于执行该客户端的固定流程。不能因为 WorkBuddy／豆包有登录按钮就走 OAuth，也不能因为 Codex／Cursor／Claude 缺少自动授权操作就改用配对码。用户明确只安装、不连接时停止。

客户端身份以当前智能体明确提供的信息为准，不根据操作系统、仓库地址或其他已安装 CLI 猜测。身份未知时只问客户端名称，确认后引导；未列出的客户端说明尚无固定适配，不让用户猜认证方案。

## OAuth 客户端

安装后立即给出 OAuth 登录确认。用户已明确同意连接或回复“授权”时继续，不重复问。使用当前客户端真实提供的新增 MCP 和登录能力；只有手动入口时给出已核实的设置步骤和固定 URL，不虚构自动弹窗。缺少当前授权能力时保持 OAuth 方式，解释阻塞及可执行的下一步，不切配对码。

首次 OAuth 统一申请 `web:search model:chat`，授权前说明同时包含检索与模型聊天，等待用户在授权页确认；不是自动扩权，也不代替费用确认。旧授权只有单项时，经用户确认重新授权并核对实际返回的范围，不通过刷新或手工改配置声称已扩权。用户明确要求只授予单项时尊重选择。

固定 URL：`https://mcp.diffmind.ai/mcp/open`，使用 Streamable HTTP。服务发现、登记、回调、凭据保存和刷新交给当前原生客户端；不猜测 redirect_uri、client_id 或 client_secret。Codex 客户端位置与远端命令执行位置分别判断；远端 localhost 不等于用户电脑。CLI 后备只在已确认的对应客户端上下文执行。

OAuth 错误如实区分登记失败、回调拒绝、账号错误和工具未加载；不放宽服务端校验，不反复登录或跨客户端复制凭据。

## 配对客户端

WorkBuddy／豆包安装后直接输出配对码引导，不询问是否打开 OAuth。引导用户去 [DiffMind 网站](https://www.diffmind.ai)「个人资料 → 凭证」生成配对码；按 pairing.md 先收齐邮箱与配对码；缺项时立即索取缺项并等待，不先做环境或连接检查。两项齐全后再检查输入、存储与调用能力，通过后兑换并保护返回的凭据；能力不完整时说明具体限制，不兑换、不擅自改 OAuth。

允许智能体要求的 Trust、启用、连接和审批，不跳过或伪造。不从 Codex 插件配置复制 OAuth 声明，也不能只写 URL 再期待自动登录。配对成功返回的就是有效访问 Token，账号授权已完成；使用 Bearer Token 调用 MCP，不再走 OAuth。必须按 pairing.md 依次取得新 Token、替换对应连接旧凭据、重连／重载、验证原生连接；只有确认当前会话无法重载时才临时使用直接 MCP HTTP 通路，不因原生工具目录为空就回退。Trust／启用只在智能体实际要求时处理，不作为固定步骤。替换已有授权需明确确认。

## 安装交付检查

最终回复必须包含该客户端的 OAuth 确认、配对引导、必要的客户端身份问题，或对应固定方式的实际阻塞及下一步。只有“文件安装成功”“下一轮可用”“校验通过”不算完成引导。安装器已完成时继续本 Skill 流程，不重复安装。

分别判断已安装、已发出引导、等待用户、已授权、当前工具已就绪。授权本身不代表当前任务已经加载工具；用真实工具发现验证，不发起付费请求探活。用户确认和本次费用确认仍须分别满足。

## 两阶段回复

安装回复仅输出 SKILL.md 对应的授权引导和当前必要下一步，不输出路径、文件数量、备份、校验结果或分流原理，不另加“回复继续配对”口令。必要的安全输入和连接条件先按实际能力核实，不把内部检查计划展开成用户操作清单。

首次 OAuth 或配对授权成功后，必须在同次回复按 SKILL.md 完整输出五项用途及示例。账号授权成功与工具加载分别判断：工具未就绪不阻止介绍，但应在介绍后简短说明真实限制和必要下一步，不把授权成功说成失败或当前工具可用。不重复展示日常连接状态和无关运行细节。

授权成功介绍统一引用 SKILL.md 的 AUTH_SUCCESS_COPY_START 至 AUTH_SUCCESS_COPY_END 固定文案，逐字输出其中正文且不输出标记；不得改写、删减或替换示例。客户端差异仅影响授权步骤和必要的真实状态补充，不改变介绍文案。
